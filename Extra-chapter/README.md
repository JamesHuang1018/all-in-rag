## 📖 Extra Chapter 是什麼？

`Extra-chapter` 目錄用於存放 **不直接屬於主線章節，但對 RAG / LLM 應用非常有價值的補充內容**。這些內容可以是你對某個相關技術（如 Neo4j、Milvus、GraphRAG 等）的系統整理，也可以是與你的研究/工作緊密相關的專題總結。

在主倉庫的「知識拓展」部分，我們會以清單形式掛出這裡的優秀專題，例如：

- `Neo4J 簡單應用`（本目錄下的第一個示例專題）
- `PowerRAG SDK 文字檢索 Demo`（上傳 Markdown → 解析/切分/向量化 → Top‑K 檢索）
- `多模態 Omni Embedding 實踐`（以 Jina v5-omni 為主的跨模態向量實踐）

我們希望透過 Extra Chapter：

- **補充主教程**：覆蓋 RAG 周邊的生態元件和工程化話題  
- **沉澱實踐經驗**：記錄真實專案中的設計思路與解決方案  
- **鼓勵多元視角**：允許不同風格的探索與實驗性內容  
- **形成可引用的知識單元**：每個專題都可以被單獨閱讀和複用

## 📂 推薦目錄結構

每一個新專題建議在 `Extra-chapter/` 下新建一個獨立子目錄，並至少包含一個 `readme.md` 作為主文件。參考結構如下（可按需要增減）：

```text
Extra-chapter/
├── your-topic-name/                # 你的專題目錄（必需）
│   ├── readme.md                   # 專題主文件（必需）
│   ├── images/                     # 圖片資源（建議有圖片時使用）
│   │   ├── figure1.png
│   │   └── figure2.jpg
│   ├── code/                       # 程式碼示例（如有程式碼建議單獨放）
│   │   ├── demo.py
│   │   └── requirements.txt
│   └── data/                       # 示例資料（如有）
│       └── sample_data.json
└── README.md                       # 本說明檔案
```

> 當前倉庫中的 `Neo4J 簡單應用` 專題位於 `Extra-chapter/Neo4J/readme.md`，你可以參考其組織方式，但不必完全照搬。

## 🧱 命名與排版建議

### 1. 目錄與檔案命名

- **專題目錄名 (`your-topic-name/`)**
  - 使用有語義的英文或中英文混合
  - 避免過長，儘量能一眼看出主題，例如：
    - `Neo4J-Simple-Application`
    - `graph-rag-practice`

- **主文件**
  - 固定為：`readme.md`（小寫），便於 GitHub 直接展示

- **圖片 / 程式碼 / 資料**
  - 統一放在 `images/`、`code/`、`data/` 等子目錄中
  - 檔名建議包含用途或內容關鍵資訊，例如：`pipeline-overview.png`、`retriever_benchmark.ipynb`

### 2. 內容組織與標題層級

推薦的章節骨架（可根據需要微調）：

- `# 專題標題`
- `## 背景與動機`
- `## 場景或問題描述`
- `## 技術方案 / 實現思路`
- `## 實踐步驟 / 程式碼示例`
- `## 經驗總結與坑點`

標題層級請保持清晰，避免過多巢狀（一般不超過三級：`##` / `###` / `####`）。

## ✅ 內容質量與範圍

為了讓內容對讀者真正有幫助，提交 PR 前請儘量滿足以下要求：

- **與 RAG / LLM 應用相關**
  - 例如：圖資料庫在 RAG 中的用法、檢索評估方案、多模態擴充套件、部署/監控經驗等

- **技術與事實儘量準確**
  - 如有推測或實驗性的結論，請明確標註
  - 關鍵程式碼建議給出可執行環境說明（Python 版本、依賴庫等）

- **結構清晰、可獨立閱讀**
  - 讀者不看主教程，也能從該專題收穫完整的一段知識

- **尊重版權與引用規範**
  - 如引用論文、部落格或開源專案，請在文末列出參考資料或連結

## 🔀 提交 PR 的具體步驟（建議）

1. **Fork 倉庫並建立分支**
   - 從 `main` 或當前預設分支拉出個人分支，例如：`feat/extra-chapter-neo4j-practice`

2. **在 `Extra-chapter/` 下建立你的專題目錄**
   - 遵循上文的目錄組織方案
   - 如有需要，可在根目錄 `README.md` 的「第六部分：知識拓展」列表中，新增指向你專題的連結（格式參考已有的 `Neo4J 簡單應用`）

3. **本地檢查排版與圖片路徑**
   - 確認 Markdown 渲染正常、圖片路徑相對位置正確

4. **編寫有資訊量的 Commit Message**

推薦包含以下資訊（可按實際場景調整）：

```text
Extra-chapter: <你的專題標題>

- 新增專題目錄：Extra-chapter/<your-topic-name>
- 主要內容：簡要說明該專題解決了什麼問題 / 分享了哪些經驗
- 程式碼與資料：如有，說明放在哪些子目錄，如何執行
- 個人資訊（可選但推薦）：你的 GitHub 連結、研究 / 工作方向等
```

5. **發起 PR**
   - PR 標題中建議包含：`[Extra-chapter]` + 你的專題名
   - 在 PR 描述裡可以：
     - 說明該專題與 All-in-RAG 主線章節的關係
     - 標註閱讀順序建議（例如：適合在讀完第 3 章之後再看）

## 💬 溝通與反饋

如果你在撰寫 Extra Chapter 的過程中：

- 不確定選題是否合適
- 想討論目錄設計或技術路線
- 希望對草稿先做一次技術性 Review

可以在倉庫的 `Discussions` 或 `Issues` 中發起話題，標題中帶上 `Extra-chapter` 關鍵字，方便維護者和其他貢獻者一起參與討論。
