# 第一節 向量嵌入

## 一、向量嵌入基礎

### 1.1 基礎概念

#### 1.1.1 什麼是 Embedding

向量嵌入（Embedding）是一種將真實世界中複雜、高維的資料物件（如文字、影象、音訊、影片等）轉換為數學上易於處理的、低維、稠密的連續數值向量的技術。

想象一下，我們將每一個詞、每一段話、每一張圖片都放在一個巨大的多維空間裡，並給它一個獨一無二的座標。這個座標就是一個向量，它“嵌入”了原始資料的所有關鍵資訊。這個過程，就是 Embedding。

- **資料物件**：任何資訊，如文字“你好世界”，或一張貓的圖片。
- **Embedding 模型**：一個深度學習模型，負責接收資料物件並進行轉換。
- **輸出向量**：一個固定長度的一維陣列，例如 `[0.16, 0.29, -0.88, ...]`。這個向量的維度（長度）通常在幾百到幾千之間。

![Embedding 過程示意圖](./images/3_1_1.webp) 

#### 1.1.2 向量空間的語義表示

Embedding 的真正意義在於，它產生的向量不是隨機數值的堆砌，而是對資料**語義**的數學編碼。

- **核心原則**：在 Embedding 構建的向量空間中，語義上相似的物件，其對應的向量在空間中的距離會更近；而語義上不相關的物件，它們的向量距離會更遠。
- **關鍵度量**：我們通常使用以下數學方法來衡量向量間的“距離”或“相似度”：
    - **餘弦相似度 (Cosine Similarity)** ：計算兩個向量夾角的餘弦值。值越接近 1，代表方向越一致，語義越相似。這是最常用的度量方式。
    - **點積 (Dot Product)** ：計算兩個向量的乘積和。在向量歸一化後，點積等價於餘弦相似度。
    - **歐氏距離 (Euclidean Distance)** ：計算兩個向量在空間中的直線距離。距離越小，語義越相似。

### 1.2 Embedding 在 RAG 中的作用

在RAG流程中，Embedding 扮演著無可替代的重要角色。

#### 1.2.1 語義檢索的基礎

RAG 的“檢索”環節通常以基於 Embedding 的語義搜尋為核心。通用流程如下：
（1）**離線索引構建**：將知識庫內文件切分後，使用 Embedding 模型將每個文件塊（Chunk）轉換為向量，存入專門的向量資料庫中。

（2）**線上查詢檢索**：當使用者提出問題時，使用**同一個** Embedding 模型將使用者的問題也轉換為一個向量。

（3）**相似度計算**：在向量資料庫中，計算“問題向量”與所有“文件塊向量”的相似度。

（4）**召回上下文**：選取相似度最高的 Top-K 個文件塊，作為補充的上下文資訊，與原始問題一同送給大語言模型（LLM）生成最終答案。

#### 1.2.2 決定檢索質量的關鍵

Embedding 的質量直接決定了 RAG 檢索召回內容的準確性與相關性。一個優秀的 Embedding 模型能夠精準捕捉問題和文件之間的深層語義聯絡，即使使用者的提問和原文的表述不完全一致。反之，一個劣質的 Embedding 模型可能會因為無法理解語義而召回不相關或錯誤的資訊，從而“汙染”提供給 LLM 的上下文，導致最終生成的答案質量低下。

## 二、Embedding 技術發展

Embedding 技術的發展與自然語言處理（NLP）的進步緊密相連，尤其是在 RAG 框架出現後，對嵌入技術提出了新的要求。其演進路徑大致可分為以下幾個關鍵階段。

### 2.1 靜態詞嵌入：上下文無關的表示

- **代表模型**：Word2Vec (2013), GloVe (2014)
- **主要原理**：為詞彙表中的每個單詞生成一個固定的、與上下文無關的向量。例如，`Word2Vec` 透過 Skip-gram 和 CBOW 架構，利用區域性上下文視窗學習詞向量，並驗證了向量運算的語義能力（如 `國王 - 男人 + 女人 ≈ 王后`）。`GloVe` 則融合了全域性詞-詞共現矩陣的統計資訊。
- **侷限性**：無法處理一詞多義問題。在“蘋果公司釋出了新手機”和“我吃了一個蘋果”中，“蘋果”的詞向量是完全相同的，這限制了其在複雜語境下的語義表達能力。

### 2.2 動態上下文嵌入

2017年，`Transformer` 架構的誕生帶來了自注意力機制（Self-Attention），它允許模型在生成一個詞的向量時，動態地考慮句子中所有其他詞的影響。基於此，2018年 `BERT` 模型利用 `Transformer` 的編碼器，透過掩碼語言模型（MLM）等自監督任務進行預訓練，生成了深度上下文相關的嵌入。同一個詞在不同語境中會生成不同的向量，這有效解決了靜態嵌入的一詞多義難題。

### 2.3 RAG 對嵌入技術的新要求

在開篇我們就提到了 RAG 框架的提出[^1]，是為了解決大型語言模型 **知識固化**（內部知識難以更新）和 **幻覺**（生成的內容可能不符合事實且無法溯源）的問題。它透過“檢索-生成”正規化，動態地為 LLM 注入外部知識。這一過程的核心是 **語義檢索**，很大程度上依賴於高質量的向量嵌入。

後續 RAG 的興起對嵌入技術提出了更高、更具體的要求：

- **領域自適應能力**：通用的嵌入模型在專業領域（如法律、醫療）往往表現不佳，這就要求嵌入模型具備領域自適應的能力，能夠透過微調或使用指令（如 INSTRUCTOR 模型）來適應特定領域的術語和語義。
- **多粒度與多模態支援**：RAG 系統需要處理的不僅僅是短句，還可能包括長文件、程式碼，甚至是影象和表格。這就要求嵌入模型能夠處理不同長度和型別的輸入資料。
- **檢索效率與混合檢索**：嵌入向量的維度和模型大小直接影響儲存成本和檢索速度。同時，為了結合語義相似性（密集檢索）和關鍵詞匹配（稀疏檢索）的優點，支援混合檢索的嵌入模型（如 BGE-M3）應運而生，在某些任務中成為提升召回率的關鍵。

## 三、嵌入模型訓練原理

瞭解了嵌入模型的發展，我們來簡單探究一下當前主流的嵌入模型（通常是基於 `BERT` 的變體）是如何透過訓練獲得強大的語義理解能力的。

現代嵌入模型的核心通常是 Transformer 的編碼器（Encoder）部分，`BERT` 就是其中的典型代表。它透過堆疊多個 `Transformer Encoder` 層來構建一個深度的雙向表示學習網路。

### 3.1 主要訓練任務

BERT 的成功很大程度上歸功於 **自監督學習** 策略，它允許模型從海量的、無標註的文字資料中學習知識。

#### 任務一：掩碼語言模型 (Masked Language Model, MLM)

- **過程**：
    - 隨機地將輸入句子中 15% 的詞元（Token）替換為一個特殊的 `[MASK]` 標記。
    - 讓模型去預測這些被遮蓋住的原始詞元是什麼。
- **目標**：透過這個任務，模型被迫學習每個詞元與其上下文之間的關係，從而掌握深層次的語境語義。

#### 任務二：下一句預測 (Next Sentence Prediction, NSP)

- **過程**：
    - 構造訓練樣本，每個樣本包含兩個句子 A 和 B。
    - 其中 50% 的樣本，B 是 A 的真實下一句（IsNext）；另外 50% 的樣本，B 是從語料庫中隨機抽取的句子（NotNext）。
    - 讓模型判斷 B 是否是 A 的下一句。
- **目標**：這個任務讓模型學習句子與句子之間的邏輯關係、連貫性和主題相關性。
- **重要說明**：後續的研究（如 RoBERTa）發現[^2]，NSP 任務可能過於簡單，甚至會損害模型效能。因此，許多現代的預訓練模型（如 RoBERTa、SBERT）在預訓練階段移除了 NSP。

> 更多細節可檢視 [BERT 架構及應用](https://github.com/datawhalechina/base-nlp/blob/main/docs/chapter5/13_Bert.md)

### 3.2 效果增強策略

雖然 MLM 和 NSP 賦予了模型強大的基礎語義理解能力，但為了在檢索任務中表現更佳，現代嵌入模型通常會引入更具針對性的訓練策略。

- **度量學習 (Metric Learning)** ：
    - **思想**：直接以“相似度”作為最佳化目標。
    - **方法**：收集大量相關的文字對（例如，（問題，答案）、（新聞標題，正文））。訓練的目標是最佳化向量空間中的**相對距離**：讓“正例對”的向量表示在空間中被“拉近”，而“負例對”的向量表示被“推遠”。關鍵在於最佳化排序關係，而非追求絕對的相似度值（如 1 或 0），因為過度追求極端值可能導致模型過擬合。

- **對比學習 (Contrastive Learning)** ：
    - **思想**：在向量空間中，將相似的樣本“拉近”，將不相似的樣本“推遠”。
    - **方法**：構建一個三元組（Anchor, Positive, Negative）。其中，Anchor 和 Positive 是相關的（例如，同一個問題的兩種不同問法），Anchor 和 Negative 是不相關的。訓練的目標是讓 `distance(Anchor, Positive)` 儘可能小，同時讓 `distance(Anchor, Negative)` 儘可能大。

## 四、嵌入模型選型指南

理論已經瞭解，那麼該如何選擇最適合你專案的嵌入模型？

### 4.1 從 MTEB 排行榜開始

[**MTEB (Massive Text Embedding Benchmark)**](https://huggingface.co/spaces/mteb/leaderboard) 是一個由 Hugging Face 維護的、全面的文字嵌入模型評測基準。它涵蓋了分類、聚類、檢索、排序等多種任務，並提供了公開的排行榜，為評估和選擇嵌入模型提供了重要的參考依據。

![MTEB 排行榜](./images/3_1_2.webp)

下面這張圖是網站中的模型評估影象，直觀地展示了在選擇開源嵌入模型時需要權衡的四個核心維度：

- **橫軸 - 模型引數量 (Number of Parameters)** ：代表了模型的大小。通常，引數量越大的模型（越靠右），其潛在能力越強，但對計算資源的要求也越高。
- **縱軸 - 平均任務得分 (Mean Task Score)** ：代表了模型的綜合效能。這個分數是模型在分類、聚類、檢索等一系列標準 NLP 任務上的平均表現。分數越高（越靠上），說明模型的通用語義理解能力越強。
- **氣泡大小 - 嵌入維度 (Embedding Size)** ：代表了模型輸出向量的維度。氣泡越大，維度越高，理論上能編碼更豐富的語義細節，但同時也會佔用更多的儲存和計算資源。
- **氣泡顏色 - 最大處理長度 (Max Tokens)** ：代表了模型能處理的文字長度上限。顏色越深，表示模型能處理的 Token 數量越多，對長文字的適應性越好。

![MTEB 排行榜多維度評估示意圖](./images/3_1_3.webp)

MTEB 榜單可以幫助我們快速篩選掉大量不合適的模型。但需要注意，榜單上的得分是在通用資料集上評測的，可能無法完全反映模型在你特定業務場景下的表現。

### 4.2 關鍵評估維度

在檢視榜單時，除了分數，還需要關注以下幾個關鍵維度：

- **任務 (Task)** ：對於 RAG 應用，需要重點關注模型在 `Retrieval` (檢索) 任務下的排名。
- **語言 (Language)** ：模型是否支援你的業務資料所使用的語言？對於中文 RAG，應選擇明確支援中文或多語言的模型。
- **模型大小 (Size)** ：模型越大，通常效能越好，但對硬體（視訊記憶體）的要求也越高，推理速度也越慢。需要根據你的部署環境和效能要求來權衡。
- **維度 (Dimensions)** ：向量維度越高，能編碼的資訊越豐富，但也會佔用更多的儲存空間和計算資源。
- **最大 Token 數 (Max Tokens)** ：這決定了模型能處理的文字長度上限。這個引數是你設計文字分塊（Chunking）策略時必須考慮的重要依據，塊大小不應超過此限制。
- **得分與機構 (Score & Publisher)** ：結合模型的得分排名和其釋出機構的聲譽進行初步篩選。知名機構釋出的模型通常質量更有保障。
- **成本 (Cost)** ：如果是使用 API 服務的模型，需要考慮其呼叫成本；如果是自部署開源模型，則需要評估其對硬體資源的消耗（如視訊記憶體、記憶體）以及帶來的運維成本。

### 4.3 迭代測試與最佳化

> 不要只依賴公開榜單做最終決定。

（1）**確定基線 (Baseline)** ：根據上述維度，選擇幾個符合要求的模型作為你的初始基準模型。

（2）**構建私有評測集** ：根據真實業務資料，手動建立一批高質量的評測樣本，每個樣本包含一個典型使用者問題和它對應的標準答案（或最相關的文件塊）。

（3）**迭代最佳化** ：
    - 使用基線模型在你的私有評測集上執行，評估其召回的準確率和相關性。
    - 如果效果不理想，可以嘗試更換模型，或者調整 RAG 流程的其他環節（如文字分塊策略）。
    - 透過幾輪的對比測試和迭代最佳化，最終選出在你的特定場景下表現最佳的那個“心儀”模型。
