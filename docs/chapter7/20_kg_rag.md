# 第一節 基於知識圖譜的RAG

傳統RAG框架雖然有效緩解了大型語言模型的知識陳舊和幻覺問題，但在處理複雜查詢時仍存在明顯侷限。依賴非結構化文字向量檢索的方式，往往難以捕捉實體間的深層關係，導致上下文檢索不精確、資訊碎片化，甚至誘發模型產生"幻覺"。為了突破這些瓶頸，將結構化知識圖譜融入 RAG 流程的新正規化——GraphRAG 誕生。透過利用知識圖譜的顯式語義關係和圖結構優勢，GraphRAG能夠提供更精準的上下文檢索和更強的推理能力，在多跳查詢和事實性要求較高的場景中表現尤為出色。

### 1.1 傳統RAG框架的固有侷限性

儘管傳統 RAG 透過"檢索-生成"兩階段流程在一定程度上解決了LLM的知識更新問題，但其基於非結構化文字向量檢索的核心機制仍存在幾個關鍵侷限。

**關係理解的缺失**：基於向量的檢索主要關注語義相似性，難以捕捉和利用實體之間複雜的、隱含的關係。當查詢涉及多實體關聯或因果推理時，檢索到的文字塊之間可能缺乏邏輯聯絡，導致LLM難以進行有效的綜合與推理。

**上下文的碎片化**：文字被切分成獨立的塊進行索引，這破壞了原文的結構和上下文連續性。對於需要跨越多個文件或長距離文字進行資訊整合的問題，傳統RAG往往力不從心。

**檢索噪聲與幻覺風險**：檢索過程可能返回不相關或僅部分相關的噪聲資訊，這會干擾LLM的判斷，甚至誘發其產生與事實不符的"幻覺"內容。知識圖譜的引入被證實能有效減輕模型幻覺，提供更高質量的上下文。

**推理能力有限**：傳統 RAG 的推理能力受限於檢索到的線性文字內容，難以支援需要結構化知識進行導航的多跳推理。

**跨文件聯結能力弱**：即便採用較大的切塊與滑窗重疊，跨文件/跨章節的實體共現與隱式引用仍難以被顯式建模，導致需要“連邊”才能回答的問題（如沿因果、時間或供應鏈關係追蹤）召回不足。

**實體歧義與別名問題**：僅依賴向量相似度很難穩定地區分同名實體（如不同城市/公司/人名），或統一別名、縮寫與多語言變體，易造成錯誤對齊與語義漂移。

**時效性與版本一致性不足**：文字塊往往缺少可計算的時間屬性與有效期邊界，導致時序敏感問題（如“某公司在某年是否仍為子公司”）難以得到一致答案。

一個典型示例：

- 問題：“2019年收購A公司的企業，其母公司在2021年的主要投資物件是誰？”
- 傳統做法需要檢索多段文字並在生成階段自行拼接與推理；若任一段缺失或存在歧義，整體推理鏈即會斷裂。

### 1.2 知識圖譜賦能 RAG 的核心優勢

知識圖譜透過節點（實體）和邊（關係）的網路結構，將離散的知識顯式地組織成一個相互連線的語義網路，為克服傳統RAG的侷限性提供了強有力的解決方案。

**結構化語義表達**：知識圖譜以圖的形式直接編碼實體間的顯式語義關係（如"公司A-收購-公司B"），避免了LLM從文字中進行隱式、可能存在偏差的推斷，為複雜查詢提供了清晰的導航路徑。

**增強推理能力**：圖的結構天然支援多跳推理，系統可以沿著圖中的路徑遍歷，發現間接但關鍵的知識關聯，從而回答需要多步邏輯推導的複雜問題。

**事實性與可解釋性**：基於知識圖譜檢索的答案可以追溯其在圖中的推理路徑，這為答案提供了事實依據，極大地增強了系統的可解釋性和可信度，有效抑制了幻覺。

**異構資料整合**：知識圖譜能夠無縫整合來自不同來源的結構化（如資料庫）和非結構化（如文字）資料，形成一個全面、統一的知識檢視，這在金融、醫療等需要整合海量異構資訊的領域尤為重要。

進一步地：

- **語義模式與本體支撐**：透過模式（Schema）與本體（Ontology）明確實體型別、關係約束與屬性域值，約束推理空間，降低歧義。
- **溯源與置信度管理**：邊與節點可攜帶來源、時間戳與置信度，便於在生成時進行來源歸因與衝突消解。
- **時間與版本建模**：支援時間態邊與版本化節點，允許對“歷史狀態”與“有效區間”進行查詢（Time-travel Query）。

### 1.3 GraphRAG：一種正規化革新

GraphRAG將檢索的目標從獨立的文字片段轉變為在知識圖譜中尋找相關的實體、關係、路徑或子圖。這一轉變從根本上提升了RAG系統的能力。已有研究與實踐報告顯示，GraphRAG 在上下文召回、多跳問答準確率、事實一致性與可解釋性等關鍵指標上較傳統RAG具有顯著優勢。這標誌著RAG技術從“資訊檢索”向“知識利用”的正規化演進。

## 二、GraphRAG框架的核心架構與工作流程

大多數GraphRAG框架遵循一個通用的三階段流程：知識圖譜構建、圖譜檢索與增強生成。

### 2.1 通用架構三階段

**知識圖譜構建** 是 GraphRAG 的基礎。該階段的目標是從原始資料中構建一個高質量的知識圖譜：

- 知識抽取：利用 LLM 或 IE 管線從非/半結構化文字中抽取實體、關係與屬性，包含指代消解、別名歸一（Normalization）與術語標準化。
- 質量控制：對三元組進行置信度評估、人機協同抽檢與衝突消解；必要時透過規則與本體約束做一致性校驗。
- 圖譜融合：進行實體對齊與去重（Entity Resolution），合併跨來源知識並保留來源/時間戳等溯源資訊。
- 儲存與索引：落地到圖資料庫（如Neo4j/NebulaGraph/TigerGraph/Neptune等）並建立必要的屬性與關係索引，便於後續高效檢索與遍歷。

**圖譜檢索** 階段，當使用者提出查詢時，系統不再是簡單地進行向量相似度搜尋，而是執行更復雜的圖譜檢索操作。混合檢索策略是主流趨勢：

- 實體定位：先用實體連結（Entity Linking）或向量檢索在圖中鎖定核心實體節點。
- 子圖探索：從命中節點出發，利用圖查詢語言（如Cypher）或遍歷演算法進行鄰域擴充套件、路徑發現與約束過濾（例如限定關係型別、跳數、時間區間與置信度閾值）。
- 結構化證據抽取：將路徑與關鍵節點屬性序列化為可讀證據片段，或生成子圖的文字摘要。
- 高階檢索：如GraphRAG採用社群檢測（如Leiden）生成多層次摘要，實現“全域性-區域性”聯合檢索。

示例（Cypher）：查詢公司A兩跳內的收購路徑及目標行業。

```cypher
MATCH (a:Company {name: "A"})-[:ACQUIRED]->(b:Company)-[:IN_INDUSTRY]->(i:Industry)
RETURN a.name AS acquirer, b.name AS target, i.name AS industry
UNION
MATCH (a:Company {name: "A"})-[:ACQUIRED]->(:Company)-[:ACQUIRED]->(b2:Company)-[:IN_INDUSTRY]->(i2:Industry)
RETURN a.name AS acquirer, b2.name AS target, i2.name AS industry;
```

**增強生成** 是最後一步，將檢索到的結構化知識（如相關實體的屬性、實體間的關係路徑、描述子圖的文字摘要等）與原始查詢一同注入到 LLM 提示（Prompt）中。實踐要點：

- 提示設計：明確要求模型引用“圖證據”，並在回答中給出來源與路徑（可作為可選的引用附錄）。
- 證據融合：將“結構化三元組/路徑”與“原文片段”聯合提供，兼顧事實性與文字細節。
- 約束回答：對敏感領域（財務/醫療）可採用模板化輸出與欄位校驗，減少幻覺。

### 2.2 方法論分類

根據綜述性研究，現有的 GraphRAG 方法大致可以歸為三類，反映了知識圖譜與 RAG 結合深度的不同。

**知識驅動型：** 檢索過程主要或完全依賴於知識圖譜。這類方法直接在圖上進行查詢與推理（如文字轉 Cypher/Gremlin），適用於需要強邏輯約束與可解釋性的任務。

**索引驅動型：** 將知識圖譜的結構資訊融入到文字索引。例如用鄰居實體/關係充當後設資料特徵、或將子圖摘要拼接到文字後再向量化，以提升召回與重排效果。

**混合型：** 同時使用圖檢索與文字檢索，並對結果統一重排與融合：

- 簡單事實問答可優先圖檢索；敘事性/描述性問題可補充文字證據。
- 對複雜查詢，可先圖上定位路徑，再以路徑節點為“導航樞紐”做針對性文件檢索。

優劣對比（概覽）：

- 知識驅動：高精度/高可解釋，但覆蓋與容錯受限於圖譜完備性。
- 索引驅動：整合成本低，但顯式推理弱、可解釋性一般。
- 混合型：綜合表現更穩健，但系統複雜度與工程成本較高。

## 三、前沿GraphRAG框架介紹（截至2025年）

近年來，學術界和工業界湧現出一批具有代表性的GraphRAG框架，它們在架構設計和應用場景上各有側重。

### 3.1 GraphRAG (Microsoft)

GraphRAG是一個重量級的框架，其核心思想是“先構建全域性知識，再按需檢索”[^1][^2]。典型流程：

- 文字→三元組/子圖構建→圖譜（屬性圖）；
- 採用社群檢測（如Leiden）進行圖劃分，按層級生成全域性/社群/區域性摘要；
- 查詢時先匹配全域性/社群摘要，再下鑽到區域性子圖與原文證據；
- 根據需要返回“全域性觀”與“證據路徑”並行的雙視角答案。

該方法的優勢是提供強全域性感知與良好可解釋性，適合探索性分析、全景總結與多跳問答；但前期構建與分層摘要成本較高，對資料持續變更的場景需設計批處理/增量更新與快取策略。

### 3.2 LightRAG

針對 GraphRAG 的“重量”問題，LightRAG 旨在實現輕量、高效、易擴充套件[^3][^4]：

- 核心思路常見為“雙層檢索”與“圖增強索引”，以較低構建成本獲得全域性-區域性兼顧的檢索能力；
- 更強調將結構訊號嵌入到文字索引與重排中，弱化複雜的社群發現流程；
- 適用於資源受限、快速迭代與線上更新場景。

### 3.3 FRAG (Flexible RAG)

FRAG強調“靈活性”與“模組化”，以自適應不同複雜度的查詢[^5]：

- 查詢分流：透過分類器或規則將請求判定為簡單/複雜；
- 簡單查詢：直接實體連結+屬性查詢，低延遲返回；
- 複雜查詢：啟用路徑檢索/多跳推理模組，再融合文字證據；
- 易擴充套件：模組化設計與預訓練LLM能力複用，遷移成本低。

### 3.4 GraphIRAG (Iterative Knowledge Retrieval)

GraphIRAG 引入“迭代檢索”思想，認為單次檢索不足以解決複雜問題[^6]：

- 由控制器在生成中多輪觸發圖查詢，逐步補齊證據鏈；
- 以“新資訊增益”為準則決定是否繼續迭代與何時停止；
- 對時間敏感與多跳推理任務更具魯棒性。

## 四、效能評估與基準測試

### 4.1 核心評估指標

GraphRAG 的評估體系是多維度的，主要涵蓋三個方面。

**檢索質量**：

- 傳統：精確率（Precision）、召回率（Recall）、F1、命中率（Hit Rate@K）。
- RAG特有：
  - 上下文精確率（Context Precision）= 檢索到的上下文中“真正相關”的比例；
  - 上下文召回率（Context Recall）= 所有應當支援答案的“金標準證據”被檢回的比例；
  - 引用/歸因準確率（Citation/Attribution）= 生成答案中的關鍵斷言是否被檢索證據正確支撐。

**生成質量**：

- 問答：精確匹配（EM）、F1；
- 摘要：ROUGE；
- 事實一致性/忠實度（Faithfulness）：斷言與證據的一致性，可配合“逐句打標+歸因檢查”。

**系統效能**：

推理延遲（Latency）是從接收查詢到返回最終答案所需的總時間，是衡量系統響應速度的核心指標。吞吐量（Throughput）指系統在單位時間內能處理的查詢數量（QPS）。成本（Cost）包括API呼叫次數、計算資源（GPU/CPU）和記憶體消耗等。

### 4.2 常用基準資料集

學術界已經建立了一系列基準資料集來評測GraphRAG在不同任務上的能力。

**多跳問答** 資料集要求模型在多個知識源之間進行推理，是檢驗GraphRAG核心能力的試金石。代表性資料集包括 HotpotQA、2WikiMultihopQA 和 MuSiQue。

**複雜問答** 資料集包含結構複雜的查詢，代表性資料集包括 WebQSP 和 ComplexWebQuestions (CWQ)。

**知識圖譜驅動的QA** 是專門為評估知識圖譜問答能力設計的資料集，如 KGQAgen-10k。

不過，一些研究指出，部分現有基準（如WebQSP）存在資料質量問題或評估方法過於僵化（如嚴格的EM），可能導致對模型效能的低估。因此，構建更高質量、更科學的基準是未來的一個重要方向。

## 五、生產環境部署實踐與挑戰

將GraphRAG框架從實驗室推向生產環境，面臨著一系列獨特的工程和技術挑戰。

- **知識圖譜的構建與動態維護**：高質量知識圖譜的構建本身就是一項耗時耗力的知識工程。在生產環境中，知識需要持續保持最新狀態，如何設計高效、準確、低成本的動態更新機制是核心難點。

- **系統效能與可擴充套件性**：隨著知識庫規模和使用者查詢量的增長，系統的響應延遲、吞吐量和資源消耗成為主要瓶頸。生產部署需要應對向量化速度慢、記憶體溢位、API 失敗等具體問題。

- **安全與隱私保護**：RAG 系統引入外部資料來源，帶來了新的安全風險，包括資料隱私洩露、模型被注入惡意資料（模型中毒）、以及針對檢索模組的攻擊等。

- **成本控制**：大規模部署 GraphRAG 系統需要大量的計算和儲存資源，如何最佳化系統架構以降低運營成本是一個重要的商業考量。
