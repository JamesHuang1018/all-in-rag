# 第一節 評估介紹

> 構建RAG系統後，下一個關鍵問題是：如何科學地評估其表現？

評估之所以關鍵，是因為它回答了RAG開發與應用中的一系列核心問題：

- **對於開發者：** 如何量化地追蹤、迭代並提升RAG應用的效能？當系統出現“幻覺”或答非所問時，如何快速定位問題根源？
- **對於使用者或決策者：** 面對兩個不同的RAG應用，如何客觀地評判孰優孰劣？


本節將探討RAG評估的理念與方法，並圍繞 **“RAG三元組（RAG Triad）”** 展開。

![RAG Triad](./images/6_1_1.webp)

## 一、RAG評估三元組

該架構包含以下三個維度，並在 **TruLens** [^1]等工具中有深入的應用：

（1）**上下文相關性 (Context Relevance)**
- **評估目標：** 檢索器（Retriever）的效能。
- **核心問題：** 檢索到的上下文內容，是否與使用者的查詢（Query）高度相關？
- **重要性：** 檢索是RAG應用在響應使用者查詢時的第一步。如果檢索回來的上下文充滿了噪聲或無關資訊，那麼無論後續的生成模型多麼強大，都沒法做出正確答案。

（2）**忠實度 / 可信度 (Faithfulness / Groundedness)**
- **評估目標：** 生成器的可靠性。
- **核心問題：** 生成的答案是否完全基於所提供的上下文資訊？
- **重要性：** 這個維度主要在於量化LLM的“幻覺”程度。一個高忠實度的回答意味著模型嚴格遵守了上下文，沒有捏造或歪曲事實。如果忠實度得分低，說明LLM在回答時“自由發揮”過度，引入了外部知識或不實資訊。

（3）**答案相關性 (Answer Relevance)**
- **評估目標：** 系統的端到端（End-to-End）表現。
- **核心問題：** 最終生成的答案是否直接、完整且有效地回答了使用者的原始問題？
- **重要性：** 這是使用者最直觀的感受。一個答案可能完全基於上下文（高忠實度），但如果它答非所問，或者只回答了問題的一部分，那麼這個答案的相關性就很低。例如，當使用者問“法國在哪裡，首都是哪裡？”，如果答案只是“法國在西歐”，那麼雖然忠實度高，但答案相關性很低。

> 你可能覺得忠實度和答案相關性很相似，但它們的側重點是不同的。忠實度更關注模型是否嚴格遵循了上下文，而答案相關性則更關注模型是否直接、完整且有效地回答了問題。

透過對這三個維度進行評估，可以對RAG系統的表現有一個全面而細緻的瞭解，並能準確定位問題所在：是檢索出了問題，還是生成環節有待改進。

## 二、評估工作流

雖然上面把評估分成了三個部分，但實際上可以把評估過程拆解為兩個主要環節：**檢索評估**和**響應評估**。

### 2.1 檢索評估

檢索評估聚焦於RAG三元組中的 **上下文相關性 (Context Relevance)**，本質上是一次**白盒測試** [^2]。此階段的評估需要一個標註資料集，其中包含一系列查詢以及每個查詢對應的真實相關文件。

這項評估借鑑了資訊檢索領域的多個經典指標：
- **上下文精確率 (Context Precision):** 衡量檢索結果的準確性。計算在檢索到的前 **k** 個文件中相關文件所佔的比例，其中 **k** 是一個預設的數字（例如，k=3或k=5），代表評估的範圍。高精確率意味著檢索結果的噪聲較少。

    $$\text{Precision}@k = \frac{\text{檢索到的}k\text{個結果中的相關文件數}}{k}$$

- **上下文召回率 (Context Recall):** 衡量檢索結果的完整性。計算在檢索到的前 **k** 個文件中，找到的相關文件佔所有真實相關文件總數的比例。高召回率意味著系統能夠成功找回大部分關鍵資訊。

    $$\text{Recall}@k = \frac{\text{檢索到的}k\text{個結果中的相關文件數}}{\text{資料集中所有相關的文件總數}}$$

- **F1分數 (F1-Score):** F1分數是精確率和召回率的調和平均數，它同時兼顧了這兩個指標，在它們之間尋求平衡。當精確率和召回率都高時，F1分數也高。

    $$F_1 = 2 \cdot \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$

- **平均倒數排名 (MRR - Mean Reciprocal Rank):** 評估系統將第一個相關文件排在靠前位置的能力。對於一個查詢，倒數排名是第一個相關文件排名的倒數。MRR是所有查詢的倒數排名的平均值。該指標適用於使用者通常只關心第一個正確答案的場景。

    $$\text{MRR} = \frac{1}{|Q|} \sum_{q=1}^{|Q|} \frac{1}{\text{rank}_q}$$

    其中 `|Q|` 是查詢總數，`rank_q` 是第 `q` 個查詢的第一個相關文件的排名。

- **平均準確率均值 (MAP - Mean Average Precision):** MAP是一個綜合性指標，同時評估了檢索結果的精確率和相關文件的排名。它先計算每個查詢的平均精確率（AP），然後對所有查詢的AP取平均值。AP本身是基於每個相關文件被檢索到時的精確率計算的。

    $$\text{MAP} = \frac{1}{|Q|} \sum_{q=1}^{|Q|} \text{AP}(q)$$

    其中 `|Q|` 是查詢總數，`AP(q)` 是第 `q` 個查詢的平均精確率（Average Precision）。

要計算上述所有指標，前提是擁有一個高質量的標註資料集，其中包含了查詢和每個查詢對應的“真實”相關文件。

### 2.2 響應評估

響應評估覆蓋了RAG三元組中的 **忠實度** 和 **答案相關性**。此環節通常採用 **端到端** 的評估正規化，因為它直接衡量使用者感知的最終輸出質量。無論採用何種評估方法，都主要圍繞以下兩個核心維度展開。

#### 2.2.1 評估維度

（1）**忠實度 / 可信度**：衡量生成的答案在多大程度上可以由給定的上下文所證實。一個完全忠實的答案，其所有內容都必須能在上下文中找到依據，以此避免模型產生“幻覺”。

（2）**答案相關性**：衡量生成的答案與使用者原始查詢的對齊程度。一個高相關性的答案必須是直接的、切題的，並且不包含與問題無關的冗餘資訊。

#### 2.2.2 主要評估方法

針對上述維度，目前主要有兩類評估方法：

（1）**基於大語言模型的評估**

這是一種強大的評估方法，能夠提供更深度的語義評估，正逐漸成為主流選擇。利用一個高效能、中立的llm作為“評估者”，對上述維度進行深度的語義理解和打分。

- **忠實度評估：** 首先，將生成的答案分解為一系列獨立的宣告或斷言（Claims）。然後，對於每一個斷言，在提供的上下文中進行驗證，判斷其真偽。最終的忠實度分數是所有被上下文證實的斷言所佔的比例。
- **答案相關性評估：** 評估者需要同時分析使用者查詢和生成的答案。評分時會懲罰那些答非所問、資訊不完整或包含過多無關細節的答案。

（2）**基於詞彙重疊的經典指標**

這類指標需要在資料集中包含一個或多個“標準答案”。它們透過計算生成答案與標準答案之間 n-gram（連續的n個詞）的重疊程度來評估質量。

- **ROUGE (Recall-Oriented Understudy for Gisting Evaluation):** ROUGE關注的重點是 **召回率**，即標準答案中的詞語有多少被生成答案所覆蓋，因此常用於評估內容的 **完整性**。其常用變體包括計算n-gram的 `ROUGE-N` 和計算最長公共子序列的 `ROUGE-L`。

    $$\text{ROUGE-N} = \frac{\text{匹配的 } n\text{-gram 數量}}{\text{參考答案中 } n\text{-gram 的總數}}$$

- **BLEU (Bilingual Evalu ation Understudy):** BLEU側重於評估 **精確率**，衡量生成的答案中有多少詞是有效的（即在標準答案中出現過）。它還引入了長度懲罰機制，避免模型生成過短的句子，因此更適合評估答案的 **流暢度和準確性**。

    $$\text{BLEU} = \text{BP} \times \exp\left(\sum_{n=1}^{N} w_n \log p_n\right)$$

    其中，`BP` 是長度懲罰因子，`p_n` 是修正後的n-gram精確率。

- **METEOR (Metric for Evaluation of Translation with Explicit ORdering):** 作為BLEU的改進版，METEOR同時考量 **精確率和召回率** 的調和平均，並透過詞幹和同義詞匹配（如將'boat'和'ship'視為相關）來更好地捕捉語義相似性。其評估結果通常被認為與人類判斷的相關性更高。

    $$F_{\text{mean}} = \frac{P \times R}{\alpha P + (1-\alpha)R}$$

    $$\text{METEOR} = F_{\text{mean}} \times (1 - \text{Penalty})$$

    其中 `P` 是精確率，`R` 是召回率，`Penalty` 是基於語序的懲罰項。

> 為了更直觀地理解三者的區別，來看一個簡單的例子。
> 
> **假設：**
> - **參考答案：** `狗 在 床 上面` (共5個詞)
> - **生成答案：** `狗 在 床 上` (共4個詞)
> 
> **評估分析：**
> - **ROUGE (召回率導向):** 從召回率的角度出發：“參考答案裡的5個詞，生成答案覆蓋了多少？”——覆蓋了4個。因此，它的召回率很高（ROUGE-1 為 4/5），得分會不錯。ROUGE更關心“說全了沒”。
> 
> - **BLEU (精確率導向):** 從精確率的角度進行評判：“生成答案裡的4個詞，有多少是有效的（在參考答案裡）？”——全部有效，精確率很高。但它會發現生成答案比參考答案短，於是透過 **長度懲罰(Brevity Penalty)** 進行扣分。BLEU更關心“說對了沒，以及長度是否合適”。
> 
> - **METEOR (綜合平衡):** 同時計算精確率和召回率，並取一個調和平均。在這個例子裡，詞序是完全正確的，懲罰項為0。METEOR會在“說全”和“說對”之間找到一個最佳平衡點。

#### 2.2.3 方法對比和總結

基於LLM的評估更注重**語義和邏輯**，評估質量高，但成本也更高且存在評估者偏見。基於詞彙重疊的指標**客觀、計算快、成本低**，但無法理解語義，可能誤判同義詞或釋義。在實踐中，可以將兩者結合，使用經典指標進行快速、大規模的初步篩選，再利用LLM進行更精細的評估。
